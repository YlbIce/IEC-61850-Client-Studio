# C++ 后端环境检查

客户端启动时会检查本机 C++ 后端 EXE、递归导入的应用 DLL、VC++ 运行库是否存在，以及文件是否为有效的 x64 PE 文件，再等待本机 gRPC 通道就绪。可从“帮助 → 检查后端环境…”重新检查。

## 提示与处理

- **缺少 VCRUNTIME140 / MSVCP140 等运行库**：通过弹窗的“下载微软 x64 运行库”打开微软官方下载，运行安装程序，选择安装或修复，再回到客户端重新检查并启动。仅安装 x86 运行库不能满足 x64 后端需求。应用不会自行下载安装程序。
- **缺少 Protobuf、OpenSSL 等配套 DLL 或后端 EXE**：重新完整解压发行包，不要单独复制 EXE；检查安全软件的隔离记录。配套文件位于 `resources/backend/bin`。
- **文件架构不匹配或损坏**：重新解压同一版本完整的 x64 发行包，不要混用其他版本的 DLL。
- **依赖检查通过但进程启动失败**：弹窗显示加载器退出码或后端输出；入口点缺失可能是 DLL 版本问题，访问冲突则属于后端崩溃，不能据此认定缺少运行库。

“查看诊断报告”打开用户数据目录中的 `backend-diagnostic.json`，包含本次检查路径、缺失项、退出码和最后一段后端错误输出。报告保存在本机，重新检查会更新报告；不包含 API Key 配置。

微软说明：https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist

微软 x64 安装程序：https://aka.ms/vc14/vc_redist.x64.exe

## 两种连接

桌面界面先连接本机 C++ 后端（`127.0.0.1:动态端口`），C++ 后端再连接用户填写的远端 IED 地址（通常为端口 102）。`ECONNREFUSED 127.0.0.1:动态端口` 表示本机后端通道不可用，不能证明用户填写的 IED IP 错误。后端未就绪时，应用阻止请求并提示检查环境，刷新操作不会再误报完成。

## 检查范围与回归验证

静态检查覆盖常规 PE 导入及应用目录内的递归依赖，运行库优先检查应用目录、其次 Windows System32。它不验证所有 DLL 导出函数或延迟加载依赖，进程启动探测用于补充发现版本不兼容等错误。可选报文捕获组件继续使用自身能力检测，不会因为可选组件缺失阻止主客户端使用。

- `node --test tests/backend-health.test.js`：模拟缺失运行库、递归 DLL 缺失、架构错误、损坏文件及加载器退出码。
- `node scripts/test-backend-health-ui.js`：隔离用户目录，注入缺失运行库，验证对话框、阻止请求、恢复真实 C++ 后端、异常退出提示及刷新失败不误报成功。不修改系统运行库。
- `npm run test:client-ui`：实际 Electron 与 MMS 数据读取回归。
